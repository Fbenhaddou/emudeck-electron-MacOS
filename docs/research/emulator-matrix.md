# macOS emulator evidence matrix

Research checked 2026-10-01. Official project documentation, repositories and release listings only. This is a shortlist for future investigation, not a supported-component list. No emulator in this matrix was installed, launched, benchmarked, or controller-tested during this research. Dolphin remains the only implementation target; see [component research](components.md).

“Native” below distinguishes an ARM64 host executable from a native macOS application that still executes through Rosetta. A project-wide game compatibility claim is not evidence of compatibility on this Mac.

| Project / systems | Official macOS / Apple Silicon evidence | License evidence | Decision and unresolved work |
| --- | --- | --- | --- |
| RetroArch / core-dependent | Official download page advertises a Universal Apple Silicon/Intel desktop build. It separates modern and legacy Intel downloads. | Repository identifies GPLv3; individual cores have their own licenses and requirements. | Strong later candidate. Select and validate each core independently, including ARM64 availability, firmware, configuration, and save paths. Do not equate frontend availability with every core working. |
| PCSX2 / PS2 | Current official build guide explicitly says ARM builds are unsupported and Apple Silicon must run Intel builds through Rosetta. Official stable/nightly Mac distribution exists. | Repository identifies GPL-3.0. | Defer from native-first default. Expose Rosetta requirement if offered later; never install Rosetta silently. Requires user-supplied PS2 BIOS. Do not substitute an unofficial ARM fork solely for convenience. |
| RPCS3 / PS3 | Official December 2024 announcement provides native macOS ARM64 binaries. Current quickstart/download pages were not retrievable in this research (403/error). | README specifies GPL-2.0-only for most files, with exceptions in file headers. | Native candidate, but minimum OS, current artifact selection, firmware workflow, graphics constraints and game-specific performance need revalidation. Native availability is not a promise of smooth PS3 performance. |
| PPSSPP / PSP | Official site supplies regular macOS DMGs and documents normal drag-to-Applications installation. Current source has a macOS CI job. Architecture of the downloaded stable DMG was not inspected here. | README describes GPL 2.0-or-later origin; inspect LICENSE.TXT and bundled third-party notices for any distribution. | Strong later candidate with a simple firmware story: README says no BIOS is required. Verify ARM64/Universal Mach-O slices and release verification before promoting native support. |
| Vita3K / Vita | Official releases list `macos-arm64-latest.dmg`; current CMake presets explicitly include `ci-macos-arm64`. Generic quickstart still describes x86-64 requirements, so do not treat that table as authoritative for the ARM build. | README specifies GPLv2. | Experimental candidate only. Verify exact release, minimum macOS, executable/dependency architecture, firmware and graphics compatibility before exposing installation. |
| Cemu / Wii U | Current README calls Mac builds experimental and explicitly notes degraded performance from MoltenVK and Rosetta on ARM Macs. | MPL-2.0; dependencies and some source files have separate terms. | Defer from native-first default. “Native macOS build” in its README does not mean ARM64. Validate translation requirement and game compatibility separately. |
| shadPS4 / PS4 | Current README requires macOS 26.0+ and excludes Intel Macs. Current Mac build instructions nevertheless target `x86_64`; older official design documentation describes Rosetta execution on ARM. Current build guide uses a KosmicKrisp Vulkan driver path. | Repository lists GPL-2.0; build-document SPDX states GPL-2.0-or-later. Confirm exact source/binary notices before distribution. | Experimental, translated candidate, not a native-ARM claim. Core and QtLauncher are separate projects. Pin a specific release and recheck OS, driver, translation and launcher requirements together; old macOS 14/MoltenVK advice must not override current docs. |

## Evidence and component implications

- **RetroArch:** [official downloads](https://www.retroarch.com/platforms.php), [official repository](https://github.com/libretro/RetroArch). Desktop/store variants have different capabilities. Treat core choice and core updates as separate versioned dependencies rather than a single universal emulator capability.
- **PCSX2:** [official build guide](https://pcsx2.net/docs/advanced/building/), [official repository and BIOS requirement](https://github.com/PCSX2/pcsx2). The Mac ARM warning is explicit, not an inference from asset filenames.
- **RPCS3:** [official ARM64 announcement](https://blog.rpcs3.net/2024/12/09/introducing-rpcs3-for-arm64/), [official repository/license](https://github.com/RPCS3/rpcs3), [quickstart requiring another retrieval attempt](https://rpcs3.net/quickstart). Announcement evidence establishes native availability, not current minimum OS or a successful installation here.
- **PPSSPP:** [official downloads](https://www.ppsspp.org/download/), [Mac documentation](https://www.ppsspp.org/docs/reference/mac/), [repository](https://github.com/hrydgard/ppsspp), [CI](https://github.com/hrydgard/ppsspp/blob/master/.github/workflows/build.yml). Mac documentation locates user data beneath `~/.config/ppsspp`, including `PSP/SYSTEM/ppsspp.ini` and save-state storage. Preserve existing user data; do not assume Application Support just because the host is macOS.
- **Vita3K:** [official releases](https://github.com/Vita3K/Vita3K/releases), [ARM64 build preset](https://github.com/Vita3K/Vita3K/blob/master/CMakePresets.json), [repository](https://github.com/Vita3K/Vita3K), [quickstart](https://vita3k.org/quickstart.html). Quickstart describes firmware installation and macOS data under `~/Library/Application Support/Vita3K`. Release-list SHA-256 values are useful integrity metadata, not proof of an Apple Developer ID signature or notarization.
- **Cemu:** [official repository](https://github.com/cemu-project/Cemu), [official releases](https://github.com/cemu-project/Cemu/releases). The repository documents Mac support more clearly than the Windows-oriented front page. Read release-specific changes before deciding whether the documented Rosetta limitation has changed.
- **shadPS4:** [official repository](https://github.com/shadps4-emu/shadPS4), [current Mac build instructions](https://github.com/shadps4-emu/shadPS4/blob/main/documents/building-macos.md), [older architecture explanation](https://github.com/shadps4-emu/shadPS4/wiki/VI.-Emulator-Design-%5BDevs%5D). Current source documentation takes precedence over old wiki requirements. No old or current upstream shell installation commands were executed.

## Evidence still required before any additional adapter

For each exact artifact: immutable release identity, official source/redirect allowlist, checksum or signature evidence, Mach-O architecture and dependency inspection, bundle identifier, minimum OS, quarantine/Gatekeeper behavior, safe staging, and update/rollback semantics. Confirm license notices and source availability obligations against that artifact, not merely a repository badge. These license identifiers are an inventory, not a finding that every possible redistribution or code adaptation is compatible.

For each emulator/system: legal test content with documented redistribution terms, launch arguments, isolated configuration and save roots, firmware requirements, exit/focus behavior, game-specific compatibility, and save-preserving reset. All seven integrations remain unimplemented here. DualSense mapping, hot plugging, controller-only exit, motion, touchpad, battery and haptics are **untested** for all seven. HDR and profile quality/performance are likewise unverified. Do not derive these capabilities from SDL usage, platform support, or generic compatibility percentages.

Keep the practical order: finish Dolphin's complete vertical slice, then evaluate PPSSPP or a narrowly selected RetroArch core. RPCS3/Vita3K require their own experimental validation; PCSX2/Cemu/shadPS4 need explicit translation disclosure while their verified upstream requirements demand it. Recheck this matrix when implementing each adapter because upstream support changes.
