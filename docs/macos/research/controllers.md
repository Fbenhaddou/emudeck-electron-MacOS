# Dolphin 2609 / DualSense research — 2026-10-02

This is pinned source research and a procedure for a separate physical test. This research agent did not connect a controller, run a controller probe, configure Dolphin, or observe input. Product controller capability remains **untested** until measured. All Dolphin links below use the installed 2609 revision, `f84df02055ab9610feec48e65648cac5a3c098fa`.

## Device discovery and backend identity

Dolphin builds its gamepad backend against **SDL3**; macOS also has a separate Quartz keyboard/mouse backend. SDL receives controller-add/remove events on its hotplug thread. That implementation supports discovery; it does not establish that reconnect works on this particular Mac. Sources: [InputCommon build configuration](https://github.com/dolphin-emu/dolphin/blob/f84df02055ab9610feec48e65648cac5a3c098fa/Source/Core/InputCommon/CMakeLists.txt#L111), [backend initialization](https://github.com/dolphin-emu/dolphin/blob/f84df02055ab9610feec48e65648cac5a3c098fa/Source/Core/InputCommon/ControllerInterface/ControllerInterface.cpp#L66), and [SDL event handling](https://github.com/dolphin-emu/dolphin/blob/f84df02055ab9610feec48e65648cac5a3c098fa/Source/Core/InputCommon/ControllerInterface/SDL/SDL.cpp#L266).

The SDL source identifier is exactly `SDL`. The display name comes from SDL's runtime gamepad/joystick name, with a fallback if absent. A Dolphin qualifier combines source, assigned numeric ID, and name. The ID allocator considers existing devices with the same source/name; it is not an OS identity or permanent player assignment. Therefore `SDL/<observed ID>/<observed name>` must be read from Dolphin rather than guessed. Sources: [SDL name and source](https://github.com/dolphin-emu/dolphin/blob/f84df02055ab9610feec48e65648cac5a3c098fa/Source/Core/InputCommon/ControllerInterface/SDL/SDLGamepad.cpp#L19), [qualifier serialization](https://github.com/dolphin-emu/dolphin/blob/f84df02055ab9610feec48e65648cac5a3c098fa/Source/Core/InputCommon/ControllerInterface/CoreDevice.cpp#L190), and [ID allocation](https://github.com/dolphin-emu/dolphin/blob/f84df02055ab9610feec48e65648cac5a3c098fa/Source/Core/InputCommon/ControllerInterface/ControllerInterface.cpp#L250).

The quickest authoritative discovery for this test is Dolphin's native **Device** list in the Port 1 mapping dialog. Its Refresh action repopulates the live controller interface. Record the selected string and prove that physical inputs move the mapping indicators. The list can contain a persisted unavailable selection, so its presence alone is insufficient. The dialog saves active settings when closed; named profile Save is optional. Source: [MappingWindow](https://github.com/dolphin-emu/dolphin/blob/f84df02055ab9610feec48e65648cac5a3c098fa/Source/Core/DolphinQt/Config/Mapping/MappingWindow.cpp#L107).

For future native capability inventory, Apple's [`GCController.controllers()`](https://developer.apple.com/documentation/gamecontroller/gccontroller) returns connected controllers. [`productCategory`](https://developer.apple.com/documentation/gamecontroller/gcdevice/productcategory) and [`GCProductCategoryDualSense`](https://developer.apple.com/documentation/gamecontroller/product-category-constants) identify the category; [`vendorName`](https://developer.apple.com/documentation/gamecontroller/gcdevice/vendorname) is optional, may be nonunique, and is presentation data. A bounded helper can allow two seconds of main-run-loop processing, return at most 16 controllers and bounded name/category strings, then exit. It should inventory already-connected devices rather than start an indefinite wireless discovery. No helper has been implemented or validated here. Apple inventory does **not** supply Dolphin's SDL qualifier; keep these separate.

## Standard GameCube mapping for a physical test

In Dolphin's controller settings, set **GameCube Port 1 → Standard Controller → Configure**. This is an emulated pad, not the USB GameCube adapter setting. The current UI is built from ControllersPane and GamecubeControllersWidget. Source: [GameCube controller settings](https://github.com/dolphin-emu/dolphin/blob/f84df02055ab9610feec48e65648cac5a3c098fa/Source/Core/DolphinQt/Config/GamecubeControllersWidget.cpp#L29).

Do not use **Default** as a DualSense preset: the pinned desktop defaults are keyboard mappings, including A=X, B=Z, Start=Return, D-pad=T/G/F/H and the main stick on arrow keys. Source: [GameCube defaults](https://github.com/dolphin-emu/dolphin/blob/f84df02055ab9610feec48e65648cac5a3c098fa/Source/Core/Core/HW/GCPadEmu.cpp#L190).

The following is a proposed positional baseline, not a universal layout or tested shipped profile. Select the observed SDL device first and map by pressing each physical control. Dolphin's SDL names are positional, so PlayStation glyphs should not be inferred from Xbox-style legacy aliases. Sources: [SDL input names](https://github.com/dolphin-emu/dolphin/blob/f84df02055ab9610feec48e65648cac5a3c098fa/Source/Core/InputCommon/ControllerInterface/SDL/SDLGamepad.h#L376) and [axis direction handling](https://github.com/dolphin-emu/dolphin/blob/f84df02055ab9610feec48e65648cac5a3c098fa/Source/Core/InputCommon/ControllerInterface/SDL/SDLGamepad.cpp#L270).

| GameCube control | DualSense physical control | Expected positional SDL input |
| --- | --- | --- |
| A / B / X / Y | Cross / Circle / Triangle / Square | Button S / E / N / W respectively |
| Z | R1 | Shoulder R |
| Start | Options | Start |
| D-pad Up / Down / Left / Right | Same D-pad directions | Pad N / S / W / E respectively |
| Control Stick Up / Down / Left / Right | Left stick | Left Y+ / Y− / X− / X+ respectively |
| C Stick Up / Down / Left / Right | Right stick | Right Y+ / Y− / X− / X+ respectively |
| L and L-Analog | L2 | Trigger L for both fields |
| R and R-Analog | R2 | Trigger R for both fields |

In actual Dolphin expressions, each direction retains its full prefix, and negative directions use an ASCII minus: for example `Left Y-`. Leave stick modifiers unmapped for the initial analog test. Calibrate by observing center and full travel rather than assigning an unmeasured deadzone. Map both the analog and digital trigger fields: an analog value alone does not create the emulated digital click. The upstream MixedTriggers implementation applies its threshold to the digital field and forces the analog value to full when it activates. Keep upstream threshold/deadzone settings for the first observation; tune only after measuring the real trigger. Source: [MixedTriggers](https://github.com/dolphin-emu/dolphin/blob/f84df02055ab9610feec48e65648cac5a3c098fa/Source/Core/InputCommon/ControllerEmu/ControlGroup/MixedTriggers.cpp#L28).

Keep **Always Connected** off while checking unplug/reconnect so an unavailable default device can be detected. Source: [connection state](https://github.com/dolphin-emu/dolphin/blob/f84df02055ab9610feec48e65648cac5a3c098fa/Source/Core/Core/HW/GCPadEmu.cpp#L132). Ordinary rumble, adaptive triggers, motion, touchpad, battery reporting and controller-only exit remain separate unverified capabilities. SDL exposing optional inputs/outputs is not a measurement that they work.

## Concrete isolated test procedure

1. Connect a DualSense with a USB data cable, or pair it using PS+Create until the light bar flashes and select it in macOS Bluetooth settings. Record USB or Bluetooth; test the other transport separately. Sony documents USB/Bluetooth support from macOS 11.3 and explicitly distinguishes advanced feature availability. [Sony connection guidance](https://www.playstation.com/en-au/support/hardware/pair-dualsense-controller-bluetooth/).
2. Stop the previous managed emulator session. Use the already-verified Dolphin executable with the **same disposable managed User directory**, passed as a separate `--user` argument. For this configuration experiment, launch the regular Dolphin UI without batch mode. Do not configure an unrelated global Dolphin profile or launch a second copy concurrently.
3. Open controller settings, configure Standard Controller on Port 1, refresh the Device list, and select the observed SDL entry. Verify at least D-pad, Cross, Circle, both sticks and both trigger travel indicators using the physical controller. Close the dialog to save, quit Dolphin normally, and retain a bounded copy of this disposable `Config/GCPadNew.ini` as test evidence. The config basename is established by [GCPad input configuration](https://github.com/dolphin-emu/dolphin/blob/f84df02055ab9610feec48e65648cac5a3c098fa/Source/Core/Core/HW/GCPad.cpp#L15); the application's managed path is `<library>/emulators/dolphin/User/Config`.
4. Relaunch the already-rendered, provenance-documented **240p Test Suite 1.20 diagnostic derivative** through the managed launch using that User directory. See [fixture provenance](homebrew-fixtures.md). On its menu, observe Down move the highlight, Up move it back, Cross enter the chosen item, and Circle return. Capture before/after frames and the user's physical observations. This establishes input smoke coverage only; no game-created save or full gameplay claim follows.
5. Quit and relaunch to check mapping persistence. Disconnect/reconnect and repeat one navigation action, checking actual availability and mapping indicators. If reconnect changes the qualifier, document it rather than silently writing a guessed ID. Controller-only exit and ES-DE focus restoration require their own later flow and remain unverified.

## Why CUA keyboard input is a separate issue

Dolphin's Quartz keyboard backend reads `CGEventSourceKeyState(kCGEventSourceStateHIDSystemState, keycode)`, whereas ordinary Qt buttons can receive a different event stream. [Pinned Quartz keyboard polling](https://github.com/dolphin-emu/dolphin/blob/f84df02055ab9610feec48e65648cac5a3c098fa/Source/Core/InputCommon/ControllerInterface/Quartz/QuartzKeyboardAndMouse.mm#L192). Apple distinguishes the hardware-source state table from combined session/private state. A synthetic CUA key that activates a dialog therefore does not establish emulated-pad input; a state-table mismatch is one hypothesis, not a demonstrated explanation of this runtime. [Apple event-source states](https://developer.apple.com/documentation/coregraphics/cgeventsourcestateid).

If real physical keyboard input also fails, check Dolphin's mapped device, focus and **System Settings → Privacy & Security → Input Monitoring** for the exact Dolphin app. Input Monitoring controls an app's ability to read keyboard/mouse/trackpad input; automation Accessibility/post-event permissions concern the automation app instead. These are distinct permissions. Do not infer that a blanket permission change is required, change TCC databases, or bypass system protections. The user should grant a permission only when the observed failure and native prompt identify its need, then restart the affected app if macOS requests it. [Apple Input Monitoring](https://support.apple.com/en-au/guide/mac-help/mchl4cedafb6/26/mac/26), [macOS 27 Privacy & Security controls](https://support.apple.com/en-gb/guide/mac-help/mchl211c911f/27/mac/27).
